## 1. P0 字段的公开采集方案（12 个字段）

| # | 字段 | 公开来源 | 采集方式 | 自动化 | 频率 | 单城耗时 | 缺数据时怎么办 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `costMonthly` | 由下面几项合成 | 算法合成 | 可 | 每季度 | — | 标"暂无数据"，不猜 |
| 2 | `rent1brCenterList` | 中国房价行情网、贝壳/链家公开页 | 人工抽样 20 条取中位 | 否 | 每季度 | 20 分钟 | 留空 |
| 3 | `rent1brCenterDeal` | 同上 + 用户实付 | 暂时留空（阶段二补） | — | 每季度 | — | 显示"成交价待用户补充" |
| 4 | `bargainGap` | 由上两项推导 | 自动 | 可 | 每季度 | — | 两项之一缺失则不显示 |
| 5 | `netDown` | 宽带发展联盟季度报告、Speedtest Index | 报告摘录 + 均值 | 半 | 每季度 | 6 分钟 | 留空 |
| 6 | `tempMonthly[12]` | 中国气象数据网 / 和风天气 API | API 拉取 10 年历史 | 可 | 每年 | 2 分钟（脚本） | — |
| 7 | `comfortMonthly[12]` | 由气温 + 湿度 + 降水算 | 算法 | 可 | 每年 | — | — |
| 8 | `bestMonths` | 由舒适度推导 | 算法 | 可 | 每年 | — | — |
| 9 | `heating` | 各市供暖条例、政府公开文件 | 人工整理 | 否 | 每年 | 10 分钟 | 填"无集中供暖"或留空 |
| 10 | `hospitals3A` | 卫健委三级医院名单 | 名单匹配 | 半 | 每年 | 8 分钟 | 留空 |
| 11 | `hsrHub` | 12306 人工查询 5 个枢纽 | 人工 | 否 | 每年 | 12 分钟 | 显示"需中转" |
| 12 | `crowdLevel` | 平台自有数据 | 自动 | 可 | 每月 | — | 上线前为空（标"新兴目的地"） |

**合成字段**

| 字段 | 合成方式 |
| --- | --- |
| `costMonthly` | 房租（成交价，缺失则挂牌 × 议价系数）+ 水电燃气网络 + 餐饮（60% 自炊）+ 交通 + 杂项 |
| `comfortMonthly` | 见数据字典 §2-D 公开算法 |
| `bestMonths` | 舒适度 ≥85 且非雨季 |
| `nomadIndex` | 成本 25% + 气候 20% + 网络 15% + 配套 15% + 安全 15% + 社区 10%（公开权重） |

**单城人工耗时合计约 56 分钟**（不含脚本能做的部分）。

## 2. 工作量与批次

| 批次 | 城市数 | 人工耗时 | 说明 |
| --- | --- | --- | --- |
| 第 0 批：脚本先跑 | 100 | 0 | 气候/舒适度/推荐月份/空气质量，全部自动 |
| 第 1 批 | 25（已有的头部城市：大理、杭州、成都、昆明…） | ≈23 小时 | 先让头部城市的页面"完整" |
| 第 2 批 | 25 | ≈23 小时 | |
| 第 3 批 | 25 | ≈23 小时 | |
| 第 4 批 | 25（含新增 31 座里的剩余） | ≈23 小时 | |
| **合计** | **100** | **≈93 小时人工** | 约 12 个工作日（单人），可拆给 2–3 人并行 |

> 占全部工作量的 54%。这两项可以考虑外包或众包给目标城市的本地用户。

## 3. 逐城进度表模板

100 行建议直接开一张**飞书多维表格**（不要自研后台），字段如下，谁采谁勾：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| 城市 | 文本 | 与 `data.js` 的 `id` 对应 |
| 批次 | 单选 | 1–4 |
| 负责人 | 人员 | |
| 房租挂牌 | 数字 + 抽样日期 + 样本量 | 三个子字段 |
| 网速 | 数字 + 来源 | |
| 供暖 | 单选 | 有/无/部分 + 供暖期 |
| 三甲医院 | 数字 + 名单版本 | |
| 高铁枢纽 | 文本 | 到 5 个枢纽的最短时长 |
| 气候脚本 | 复选 | 自动跑通 |
| 状态 | 单选 | 未开始 / 进行中 / 待复核 / 完成 |
| 复核人 | 人员 | 与采集人不能是同一个 |

**验收规则**：状态="完成"必须满足——每个数字都有来源链接，且经过第二人复核。

## 4. 公开数据源速查（含注意事项）

| 数据 | 推荐来源 | 注意 |
| --- | --- | --- |
| 行政区划 | 民政部行政区划信息查询平台 | 每年更新，记版本 |
| 人口 / GDP | 国家统计局、各省统计年鉴 | 标年份 |
| 气温/湿度/日照 | 和风天气 API（免费额度）、中国气象数据网 | 用 10 年月均，不用今年 |
| 空气质量 | 全国城市空气质量实时发布平台、OpenAQ | 注明 AQI 标准 |
| 三甲医院 | 卫健委三级医院名单 | 按批次，注意有效期 |
| 异地医保 | 国家医保服务平台 | 政策变动快，半年复检 |
| 供暖 | 各市供暖条例 | 写供暖期起止 |
| 铁路/航空 | 12306、民航局名单 | 12306 反爬，人工查 |
| 房租 | 中国房价行情网、贝壳公开页 | **人工抽样，不批量爬** |
| 网速 | 宽带发展联盟季度报告 | 是城市均值，不是实测 |
| POI（咖啡馆/办公/菜场/驿站） | 高德开放平台、腾讯位置服务 | 用有资质服务商，注意配额 |

**法律与条款底线**（不是法务意见，但必须遵守）：

1. 不绕过任何网站的反爬与登录限制；
2. 抓取前看 robots.txt 与用户协议，优先用官方 API；
3. 不大规模抓取房产挂牌数据（抽样 + 人工记录即可）；
4. POI 数据遵守服务商的缓存与展示限制；
5. 所有公开数据必须在页面标注来源与日期 —— 这既是合规，也是可信度。

## 5. 阶段二（用户补充）的埋点清单

上线后要能接住用户补充的数据，前期必须先把入口做出来：

| 入口 | 采集什么 | 在哪出现 |
| --- | --- | --- |
| 城市页"补充实付租金" | `rent*Deal` + 议价空间 | 城市详情页租金模块下方 |
| 城市页"测一下网速" | `netDown` / `netUp` | 网速模块 |
| 城市页评分 | 治安、餐饮、夜生活、菜市场、奶茶、方言难度 | 城市详情页底部 |
| 发帖时选择城市 | 让帖子自动挂到城市页 | 发帖表单（已有） |
| 上传实拍 | `mediaSource/Credit/License` | 个人主页（需先加授权勾选） |

> 这一步决定阶段二能不能跑起来：**如果城市页没有"我来补一条"的入口，
> 用户永远不会主动来补数据。**
