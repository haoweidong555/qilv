## 1. 视觉基调：把"大片感 + 科技感 + 质感"翻译成规则

这三个词如果不翻译成可执行规则，最后会变成"什么都想要，什么都不像"。
我的做法是**分区切换气质**，而不是一锅混：

| 区域 | 气质 | 底色 | 主要目标 |
| --- | --- | --- | --- |
| 首屏 / 画廊 / 城市页顶部 | **影院**：大片、暗、发光 | 深色（#0e1013 系） | 视觉冲击、吸引点击 |
| 城市页数据区 / 社区 / 工具 | **纸面**：清晰、耐读 | 浅色（现有纸白） | 读数据、读长文 |
| 全局过渡带 | 由深到浅的弧线或渐变 | — | 让两种气质不打架 |

### 大片感：5 条具体规则

1. **全出血画面**：媒体铺满宽度，不放进带圆角的框里（现在卡片是圆角浮块 → 画廊区改为贴边或更大比例）。
2. **大字号标题**：城市名 32–48px（现在 19px 太小，画廊放大的话字也该放大）。
3. **低饱和 + 高对比调色**：整体压一点饱和，把亮部留给数据高光。
4. **慢速视差**：滚动时媒体与文字速度差 8–12%，幅度小、时间长（600ms+）。
5. **留白**：一屏不超过 5 张卡，宁可少，不要挤。

### 科技感：4 条具体规则

1. **数据以"触角"形式出现**：细线（1px，带一点发光）从画面引出，末端挂标签，而不是一块色块糊在照片上。
2. **数字滚动**：进入视口时数字从 0 滚到目标值（400ms，一次性，不循环）。
3. **微光与描边**：可交互元素用 1px 半透明白描边 + 悬停时微光扩散，不用重投影。
4. **等宽数字**：所有数字用 tabular-nums，避免滚动时宽度跳动。

### 质感：3 条具体规则

1. 保留现有的全站颗粒（5% 噪波），但影院区用得更轻（3%），避免暗部脏。
2. 玻璃拟态只用在**浮层**（hover 数据层、地图卡片、筛选抽屉），不用在正文区块。
3. 阴影只服务于层次：媒体用内阴影压边，浮层用大而柔的外阴影。

### 动效基线

| 交互 | 时长 | 曲线 |
| --- | --- | --- |
| 悬停推近 | 120ms | ease-out |
| 数据层淡入 | 180ms | ease-out |
| 数据逐条错峰 | 每条 60ms 延迟 | ease-out |
| 收起 | 120ms | ease-in |
| 视图切换（画廊/列表/地图） | 260ms | ease-in-out |
| 偏好滑杆重排 | 320ms | spring（轻微回弹） |

> 系统「减弱动态效果」时：所有位移动画取消，只保留透明度变化；视频不自动播放。

## 2. 信息架构

```
栖旅
├── 探索（默认首页）
│   ├── 画廊视图（默认）        ← 城市卡片流，鼠标悬停出数据
│   ├── 列表视图                ← 高密度表格，适合横向比较
│   ├── 地图视图                ← 城市级点位，非用户实时位置
│   ├── 筛选面板（6 项 + 展开全部）
│   ├── 偏好滑杆（实时重排）
│   └── 对比（选 2–5 城 → 对比视图）
├── 社区
│   ├── 板块：问答 / 避坑 / 租房 / 房车 / 宠物 / 灵活就业
│   ├── 帖子流（可按城市、板块筛选）
│   ├── 帖子详情（评论、点赞、收藏）
│   └── 发帖（必须选城市）
├── 活动
│   ├── 活动列表（同城优先）
│   ├── 活动详情（时间、地点、人数、费用）
│   └── 报名 / 取消
├── 我的
│   ├── 收藏的城市 / 笔记
│   ├── 我的帖子与评论
│   ├── 我来补数据（网速 / 实付租金 / 评分 / 素材）
│   └── 资料与通知
└── 全局搜索（城市 + 帖子 + 用户）
```

**一级导航只放 4 个**，地图、对比、工具都不进一级导航 —— 它们是"探索"里的视图或动作。

## 4. 核心交互 A：卡片悬停浮现数据

这是你提的核心交互，也是整个画廊的"价值证明"——**用户不需要点进去，就能判断这座城市要不要看**。

### 4.1 静置态

- 画面在动（实拍循环，随机倍速）
- 只显示 4 样东西：城市名、省份、一句话气质、**旅居指数**（唯一主数字）
- 角标：`实拍画面` / `实时绘制`（区分素材来源，沿用现有做法）

### 4.2 悬停态的时序（总时长约 600ms）

| 时间 | 发生什么 |
| --- | --- |
| 0–120ms | 画面推近 `scale 1.0 → 1.04`；底部遮罩加深一档（保证文字对比） |
| 120ms | 数据层容器淡入：`opacity 0→1`、`translateY 8px→0` |
| 120–600ms | **6 条数据逐条浮现**，每条错峰 60ms，各自从左侧细线向右展开 |
| 全程 | 收藏星标始终在最上层，可点；卡片其余区域整体可点（进详情） |

### 4.3 浮现的内容：正好 6 条 = 首屏 6 个筛选维度

| 顺序 | 数据 | 显示形式 | 字段 |
| --- | --- | --- | --- |
| 1 | 月成本 | `¥4,200 / 月` + 小字"含房租" | `costMonthly` |
| 2 | 舒适度 | `92` + 一条 12 格迷你条（当月高亮） | `comfortMonthly` |
| 3 | 天气 | `26℃ 晴 · 湿度 45%`（实时） | 天气 API |
| 4 | 交通 | `高铁 2h → 昆明` | `hsrHub` |
| 5 | 奶茶 | `门店密度 高 · 代表：XX、XX` | `milkTeaCount` / `milkTeaBrands` |
| 6 | 景点 | `苍山 · 洱海 · 沙溪古镇` | `attractionsTop` |

**关键设计**：这 6 条与筛选器**逐条一一对应**。用户在筛选里勾什么，悬停时就先看到什么
—— 同一套心智模型，不需要学两遍。

### 4.4 视觉形式：数据触角，不是文字块

```
        ┌──────────────────────────┐
        │                          │
        │        （动态画面）        │
        │                          │
        │   ●─── ¥4,200 / 月        │   ← 1px 细线 + 3px 发光点 + 右对齐标签
        │   ●─── 舒适度 92 ▁▃▅▇▅▃▁  │   ← 迷你条随数字一起生长
        │   ●─── 26℃ 晴 · 45%       │
        │   ●─── 高铁 2h → 昆明      │
        │   ●─── 奶茶 密度高         │
        │   ●─── 苍山 · 洱海 · 沙溪  │
        └──────────────────────────┘
```

- 细线从画面左下方的锚点引出，末端接标签；标签右对齐成一条竖线，视觉上像仪表盘。
- 单条高度 26px，6 条共 156px，放在画面下半部（上半部留画面）。
- 数据层底色：`rgba(10,12,16,0.42)` + `backdrop-filter: blur(10px)`，圆角 12px。

### 4.5 离开与边界

| 情况 | 处理 |
| --- | --- |
| 鼠标移出 | 数据层 120ms 淡出，画面 160ms 回正；不留残影 |
| 快速划过 | 交给 CSS `:hover` + `transition`，不做 JS 逐帧，避免闪烁 |
| 该字段无数据 | 该行**不显示**（不要显示"暂无"），6 条变 5 条；整体少于 3 条时改用简化版（只显示有数据的） |
| 键盘聚焦 | `:focus-visible` 触发与 hover 相同的数据层（无障碍必须） |
| 触屏 | 见 4.6 |
| 性能 | 只用 `transform` / `opacity`；**悬停不重新挂载视频、不重绘 canvas** |
| 同屏数量 | 一次只可能有一张展开（鼠标只有一个），不会刷屏 |

### 4.6 移动端替代方案（没有 hover）

移动端采用**两段式点击**：

1. 卡片默认显示 2 个核心数字（月成本 + 舒适度）——先给一半信息；
2. **第一次点击**：展开完整 6 条数据层（不跳转）；
3. **第二次点击**（或点"进入城市页"按钮）：进入详情。

好处是"一眼看数据"的能力在手机上也保留了，而不是被迫先跳进详情页。

## 5. 核心交互 B：筛选收敛

36 个维度一次铺开必崩。三层结构：

1. **首屏 6 项**（你定的）：月成本、特色奶茶店、舒适度、天气、交通、旅游景点
2. **"更多筛选"抽屉**：按成本 / 气候 / 配套 / 人群分组，共 30+ 项
3. **每组筛选显示实时命中数**：`月成本 ≤5000（23 座）`，勾选后其他选项的数字同步收敛

**空结果的处理**：不是显示"没有结果"，而是显示"最接近的 3 座"+ 哪一条卡掉了它们
（例如"没有同时满足『月成本 ≤3000』和『有地铁』的城市，去掉『有地铁』后 12 座"）。

## 6. 核心交互 C：偏好滑杆（可视化交互的重头）

4 个滑杆：**预算**（月成本上限）、**网速要求**、**怕热/怕冷**、**要热闹/要清静**。

- 拖动时画廊**实时重排**（320ms spring），被挤出去的城市淡出，新进入的淡入；
- 每张卡右上角浮出"匹配度 92%"（加权结果，权重公开）；
- 一个"重置"按钮 + 一句说明："当前按你的偏好排序，点击城市名可看默认排名"。

这个交互把"旅居指数权重之争"变成了用户自己的事 —— 也是我们最独特的可视化。

## 7. 核心交互 D：对比

- 入口：卡片右上角的"加入对比"，或列表视图多选；
- 对比视图：2–5 城 × 6 组维度，差异高亮（最优项标绿、最差标红，但只用文字色不铺色块）；
- **一键生成图片**（长图，带站名与二维码），直接可发微信群 —— 这是最便宜的传播方式；
- 未登录也能用，登录后保存对比清单。

## 8. 核心交互 E：城市页"我来补一条"

对应你定的两阶段策略，城市页的每个数据模块下都有入口：

| 模块 | 入口文案 | 收什么 |
| --- | --- | --- |
| 租金 | "你在这里租过房吗？" | 实付租金、付款方式、议价空间 |
| 网速 | "测一下你现在的网速" | 下行/上行 + 截图 |
| 生活评分 | "给这座城市打个分" | 奶茶、餐饮、夜生活、菜市场、方言 |
| 安全 | "夜里走过这条街吗" | 治安 + 女性夜间安全（分人群统计） |

**没有这些入口，阶段二永远跑不起来。**

## 9. 移动端原则（先做网页，但要为手机设计）

1. 手机是主要场景（在路上、在找房），**先按手机宽度设计，再放大到桌面**；
2. 画廊在手机上 1 列（大图，视觉冲击更强）或 2 列（信息密度优先）——建议 1 列，把"大片感"保住；
3. 筛选变底部抽屉，常用 6 项直接露出；
4. 数据层用 4.6 的两段式；
5. 首屏高度控制在 70vh 以内，让用户能立刻看到第一张卡。
