2026-09-28 开工。目标：让**注册、发帖、回复、点赞、收藏、笔记**从"只存在自己浏览器里"
变成**所有人共享**，并且把"注册才能看更多"这条规则挪到服务端执行。

## 一、已经做好的部分（代码都写完了，等你的项目地址）

| 文件 | 做什么 |
| --- | --- |
| `assets/js/config.js` | 运行配置：`backend: 'local'`（现状）或 `'supabase'`（接云端）+ 两个密钥位 |
| `assets/js/sync.js` | 云同步层：登录、拉取、推送（本地优先，断网也能用） |
| `supabase/schema.sql` | 数据库结构与权限，在 Supabase 控制台一键执行 |
| `assets/js/app.js` | 已经接好：发帖 / 回复 / 点赞 / 举手报名 / 收藏城市 / 私人笔记 / 偏好权重都会往云端同步 |

**本地优先**是什么意思：界面照旧先读写浏览器（打开即显示、断网可用），
再把改动推到云端、把云端的合并回来。所以网络慢不会让网站变得难用。

## 二、你要做的五步（约 8 分钟）

### 1. 注册并登录 Supabase

打开 <https://supabase.com/dashboard>，点 **Sign in with GitHub**，用你的 GitHub 账号授权即可（免费）。

### 2. 新建项目

- **Name**：`qilv`
- **Database Password**：点 "Generate a password" 生成，**先复制存好**（我这边用不到，但以后需要）
- **Region**：选 **Southeast Asia (Singapore)**（离国内最近，速度最好）
- 点 **Create new project**，等 1–2 分钟初始化

### 3. 关掉邮箱确认（原型阶段）

左侧 **Authentication** → **Sign In / Providers** → 找到 **Email** → 把 **Confirm email** 关掉 → **Save**。

> 为什么先关：Supabase 自带的发信服务每小时只能发几封，做测试会被卡住。
> 等要正式开放注册时，我们会接一个真正的发信服务再打开它。

### 4. 建表

左侧 **SQL Editor** → **New query** → 把项目里 `supabase/schema.sql` 的全文粘进去 → **Run**。

跑完应该显示 Success。这一步会建 7 张表、开好行级权限、并创建两个给页面用的接口
（登录用户读完整的 `posts_feed`，游客只能读 `guest_posts` 的 3 条——**"注册才能看更多"从此在服务端生效**）。

### 5. 把两个值发给我

左侧 **Project Settings** → **API**，复制这两项发我即可：

- **Project URL**（形如 `https://xxxxxxxx.supabase.co`）
- **anon public** key（一长串 JWT）

> 这两个值都是**给前端用的公开值**，写进代码、公开到 GitHub 都没问题——
> 真正的安全靠数据库行级权限。**但 `service_role` key 绝对不能发我、也不能进代码**。

## 四、数据表一览

| 表 | 存什么 | 谁能读 | 谁能写 |
| --- | --- | --- | --- |
| `profiles` | 昵称、颜色、常驻城市 | 所有人 | 只有本人 |
| `posts` | 帖子（城市 / 话题 / 正文） | 登录用户全部，游客只能看最新 3 条 | 只能以自己的名义发 |
| `replies` | 回复（也用于"举手""报名"） | 登录用户 | 只能以自己的名义回 |
| `likes` | 点赞（一人一帖一票） | 登录用户 | 只能点自己的 |
| `saved_cities` | 收藏的城市 | 只有本人 | 只有本人 |
| `notes` | 私人笔记 | 只有本人 | 只有本人 |
| `prefs` | 偏好权重（那四根滑杆） | 只有本人 | 只有本人 |
