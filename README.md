# 栖旅 · 中国旅居社区（原型 v1）

一个画廊式的中国旅居网站原型：**每张城市卡片都是一幅实时绘制的动态画面**，
点开后是城市旅居数据 + 以交流为核心的社区讨论区。

纯静态站点，不需要安装任何东西，也没有构建步骤。

## 怎么打开

方式一：直接双击 `index.html`（Safari / Chrome 都可以）。

方式二：起一个本地预览服务，这样「收藏 / 发帖」的记录一定能保存：

```bash
cd 可视化旅居网站
python3 -m http.server 8777
# 然后打开 http://127.0.0.1:8777/index.html
```

> 用 `file://` 直接打开时，部分浏览器会禁用 localStorage，
> 此时收藏和发帖仍然可用，只是刷新后不保留（代码里已做降级处理，不会报错）。

## 页面结构

- **整页背景**：固定在视口上的十二幅画（随时辰换），暗区透出画、浅区铺一层随时辰变的纸；
  **首屏**是当天两座城市的实拍短片（00:00 与 12:00 各换一座，见下文）。详见
  「整页大背景 + 首屏的城市」一节。
- **画廊**：一排五幅、统一 5:4 画幅。每排最左边一幅是**内容卡片**，
  其余四幅是城市卡片。支持分类筛选、搜索、四种排序。
  - **悬停出数据**：鼠标停在城市卡片上（键盘 Tab 聚焦也可以），
    卡片下半部会浮出六条数据触角 —— **月成本 / 舒适度 / 天气 / 交通 / 奶茶 / 景点**，
    逐条错峰浮现，舒适度带一条 12 格迷你条、当月高亮。没有数据的行直接不显示。
  - **手机两段式**：触屏没有悬停，第一次点开数据卡（六条全出、可折行），
    第二次点才进城市详情；一次只有一张展开。
  - **首屏六项快筛**（与上面六条一一对应）：月成本（四档，圈成一个整组）、
    全年舒服、现在就好、能坐高铁、奶茶店多、景点类型（下拉）。
    每个选项上的数字是**勾选后会命中几座**，会随其他条件实时收敛；
    勾到 0 结果时不说"没有"，而是提示"去掉哪一条后还有几座"。
- **城市详情**（点卡片，第二版）：动态大图 + 四个关键数字、两栏布局
  （左边是可视化，右边是可随手用的工具），见下文「城市详情页」一节。
- **交流**：全站社区时间流，按话题筛选、按城市筛选、按最新/最热排序，
  右侧栏是话题计数和「本周被聊得最多的城市」。
- **收藏**：收藏的城市并列比较，以及收藏的笔记。

## 城市详情页（第二版，2026-09-27 重做）

第一版是一列长文 + 六个数字，用户反馈「可视化不足、排版不喜欢、功能不够」，所以整页重排：

**首屏**：实拍短片 + 城市名 + 一句话气质，下面是**四个大数字**（旅居指数 / 月均成本 / 实测网速 / 推荐月份），
一眼就能判断值不值得往下看。右上角四个动作：收藏 / 加入对比 / 分享 / 在这里发一条。

**两栏**（桌面端）：

| 左栏：把数据画出来 | 右栏：随手能用的工具（粘性，滚动时不走） |
| --- | --- |
| 一句话气质 + 「适合 / 注意 / 推荐」三张判断卡 | 气质接近的城市（3 座，可点进去） |
| **旅居指数 N 是怎么来的**：四项构成条 + 各贡献多少分 | **数据来源与状态**：每项标「示例 / 估算 / 待核实 / 实时」 |
| **一年里的十二个月**：12 格月历，每格有温度、舒适度柱、当月花销倍数，点开看那一月细节 | **我的笔记**（登录后）：私人备注，只存本机 |
| **钱花在哪儿**：房租 / 吃饭 / 交通 / 水电网络 / 杂项 的堆叠条 + 金额占比 | |
| 住下来会遇到的细节（九条）+ 这座城市的交流区 | |

### 几个关键决定

1. **指数必须能解释**：与其甩一个 85 分，不如把四项（气候 / 成本 / 网速 / 长住窗口）拆开，
   每项显示贡献多少分，加起来正好等于城市页上那个指数。权重是当前口径，接入真实数据后会公开算法。
2. **月份是交互的**，不是一张静态图：点任意一格，下面给出「这个月去会怎样」——气温、体感、当月花销比均价高还是低。
3. **估算要标明是估算**：成本拆解、气候推算、网速这些都挂在「数据来源与状态」里，
   每项一个状态徽章（示例 / 估算 / 待核实 / 实时），并给出「来补一条」的入口。
   宁可让人看到「这还没核实」，也不要让人误以为 5,800 元是精确值。
4. **对比是关键功能**：最多同时选 3 座城市，弹出 10 行指标并排表（指数、成本、网速、海拔、
   最舒服分数、推荐月份、人流、气候、适合谁、注意什么）。选中状态存在本机，按钮会变成「已在对比」。
5. **分享**：城市页会把 id 写进地址栏（`?city=suzhou`），分享按钮复制这个链接；
   带 `?city=` 打开时自动弹出这座城市。
6. **私人笔记**：想住哪一片、几月去、要问谁，写在这座城市下面，只存本机、不公开。

> 这一版仍遵守账号分级：游客能看指数构成的前两项、社区前三条，其余用「注册后可见」挡住；
> 收藏、对比、发帖需要登录（都免费）。

## 城市覆盖（69 座）

覆盖**全部 34 个省级行政区**：

- **23 个省**：每省两座 —— 省会 + 一座旅游城市（如 河北：石家庄 / 承德，福建：福州 / 厦门）
- **5 个自治区**：每区两座（如 新疆：乌鲁木齐 / 喀什）
- **4 个直辖市**：北京、天津、上海、重庆，各一条
- **2 个特别行政区**：香港、澳门，各一条

地名只到「**省 · 市**」两级，不再往下切（不写"洱海西岸""日月湾"这类景区/片区）。
少数著名目的地行政上不是地级市（阳朔县、婺源县、安吉县、稻城县、海西州），
按真实行政名写，格式仍是两级。

### 新增城市怎么写

`data.js` 里新城市只写一段「种子」，剩下的自动展开：

```js
{ id: 'chengde', name: '承德', region: '河北省 · 承德市', cat: 'mountain', climate: 'northCold',
  palette: 'dawnMist', cost: 2800, net: 150, altitude: 350, crowd: '低', best: [5, 6, 7, 8],
  tagline: '…', tags: ['避暑', '皇家园林'],
  intro: '…', climateNote: '…', rent: '…', netNote: '…', transport: '…', bestFor: '…', watch: '…' }
```

自动展开的部分：

- **12 个月气温**：按 `climate` 选气候带模板（12 个带：东北/华北/西北/华东/华南/热带/云贵/高原…），
  可用 `dt` 微调几度；
- **舒适度曲线**：由气温算出来（偏离 21℃ 越远越低，极端冷热额外扣分）；
- **旅居指数**：由「推荐月份的舒适度 + 网速 + 成本」加权得出，所以贵城市指数天然偏低；
- **画面配置**：按 `cat`（海岸/湖泊/山野/草原/古城/沙漠/雪山/城市）套预设，可用 `palette`、`terrain`、`scene` 覆盖；
- **卡片列表与筛选**：自动进入画廊、省份下拉、跑马灯。

> 这部分是**示例口径**：气候曲线是按时气候带推的初稿，不是实测值；
> 指数是算出来的排序指标，不是权威评分。上线前逐城校准这一条始终成立。

### 城市多了之后的两处性能处理

- **画面按需创建**：69 座城市不会一次建 69 个画布（那是上百 MB 显存）。
  卡片先用调色板铺一层底色，等滚到附近才真正创建画面，实测首屏只建 11 个。
- **画面只在视口内绘制**：`IntersectionObserver` 控制，滚出视口即暂停。

换成实拍短片之后，这两条同样作用于视频：只有滚到附近的卡片才会开始加载和播放。

### 随机倍速

每张卡片的播放速度是**随机**的（0.75–1.65 倍），每次打开页面重新分配。
素材本身已经是 4 倍速的延时片段，再叠一层随机之后，一排卡片各有各的节奏，
不会像同一条视频被复制了几十遍。详情页里的大图则按原速播放，把节奏留给卡片。

想改范围就改 `app.js` 里的 `randomRate()`。系统开了「减弱动态效果」时，
页面会自动进入静止状态（不自动播放）。

### 素材体积（需要留意）

已经压过一轮：**69 条短片 79MB + 69 张封面 6MB = 85MB**（原先 244MB）。
规格是 640×360、单条 0.5–1.3MB、4–5 秒循环，卡片尺寸下看不出损失。

还想更小的话：换 AV1 / WebM（同画质能再小一半），或者放到 CDN 上按需加载。

### 加载策略（69 条视频不能一次全塞进去）

- **卡片先用封面图占位**，滚到视口附近才创建 `<video>`：首屏只建 8–15 个 video 元素，
  而不是 69 个。这一条既省流量也避免并发请求互相挤掉。
- 出视口自动暂停，回来自动继续。
- 素材加载失败会**重试两次**再判定不可用 —— 并发加载时的偶发失败很常见，
  不能一次失败就把实拍换成绘制画面（这个坑踩过）。

工具栏里新增了**省份下拉**（34 个省级行政区 + 全部），和分类筛选、搜索、排序叠加生效。

### 画廊的排布规则

- 版面宽度由两个变量控制：`--wrap-max`（默认 2000px）和 `--wrap-pad`（桌面 28px，
  窄屏自动降到 20 / 16px）。所以在 1900px 的屏幕上，五列画幅每格约 350px；
  想让画幅更大，调大 `--wrap-max` 或调小 `--wrap-pad` 即可。
- 画幅统一 **5:4**，断点列数：≥1100px 五列、900–1100px 四列、720–900px 三列、
  520–720px 两列、更窄一列。
- **每排最左边一幅是内容卡片**，其余是该排的城市。内容卡片共 7 种：

  | 位置 | 卡片 | 内容 |
  | --- | --- | --- |
  | 固定第 1 格 | 本周新发布 | 最新 3 条笔记（头像＋城市＋时间），点进城市详情 |
  | 固定第 2 格 | 实拍短片 | 大理实拍在播，点开看详情 |
  | 中间按天轮换 | 社区金句 / 网速排行 / 话题分布 / 发帖引导 | 每天换一张 |
  | 最后一格 | 合作位（广告） | 读 `data.js` 的 `SPONSOR` |

  合作位配置只有一处，换成真实投放只改这里：

  ```js
  SPONSOR: {
    advertiser: '示例合作方',
    eyebrow: '合作 · 广告',       // 保留“广告”字样，别藏
    title: '旅居者保险，从 ¥2/天',
    text: '医疗保障、行李延误、行程取消，按月投保，随时可停。',
    cta: '了解保障',
    image: 'assets/img/band-dali-night.jpg'
  }
  ```
- 列数变少时内容卡片会自动收敛（三列时 2 张、两列时 1 张），
  否则窄屏会变成满屏都是内容卡片。
- 搜索状态下不插入内容卡片 —— 用户要找的是具体城市。

列数不是写死在 JS 里的：`galleryColumns()` 直接读 CSS 的
`grid-template-columns` 实际值，所以改断点只需要改 CSS，两边不会失配；
窗口尺寸变化后如果列数变了会自动重排。

## 照片与画廊之间的滚动卡片带

首屏照片和画廊之间有一条**从左向右匀速滚动**的卡片带（`.marquee`），
参考的是 nomads.com 首图下方那排滚动的城市卡片。

- 内容刻意做得很杂，一共 22 张：本月最舒服的城市、旅居指数前 8 的城市、
  最新笔记、被赞最多的笔记、话题计数、实拍短片、实拍照片、最省的城市、
  网速最快的城市、发帖引导，以及一张数据总览。全部来自 `data.js` 的真实数据，
  不写死；你新增城市或有人发帖，这条带子会自动变。
- 每张卡片都可点：城市进详情、话题跳交流页、总览回到画廊、最后一张唤起发帖弹窗。
- 无缝循环的做法是「把轨道内容复制一份，位移一半」，即 `translateX(-50%) → 0`；
  鼠标悬停或键盘聚焦时自动暂停，系统开启「减弱动态效果」时完全不滚动。
- 想增删卡片类型，只改 `app.js` 里的 `marqueeItems()`；样式在 `.mq-card` 一节。

## 整页大背景 + 首屏的城市（两者都跟时间走）

这一层是 2026-09-27 晚上重做的，对应两条要求：
**随时间变的是整个界面的大背景**，**首屏那张城市背景一天换两座城市、用画廊里的短片**。

### 1. 整页大背景：一天十二幅画铺满整个界面

`index.html` 里的 `<div class="page-sky" data-day-canvas>` 固定在视口上，
由 `daycycle.js` 每两小时换一幅（十二幅，见下节），**整站共用同一片天**。

- **暗区（影院区/画廊/照片带）**：`background` 是半透明深色（上浅下深），
  底下那幅画直接透出来 —— 中午偏清蓝、黄昏偏金、深夜偏靛，还能看见星星。
- **浅区（交流页、收藏页、页脚）**：铺一层「随时辰变的纸」。
  颜色由 `app.js` 的 `applyPageAmbient(phase)` 从当前时辰的调色板算出来：
  取天空的顶色/底色按 18–34% 混进纸色 `#f7f3ec`，写成 `--wash-1/2/3`。
  比例是调出来的：再深就看不清长文，再浅就感觉不到天色变化。
- 想立刻看别的时辰：`?t=18:30` 打开，或点「一天十二幅」那排按钮。

### 2. 首屏的城市背景：一天两座城市

首屏不再是一张固定照片，而是**当天两座城市的实拍短片**（素材就是下面画廊里的那些）：

- `app.js` 的 `heroToday()` 用「今天是第几天」做种子，从 57 座有短片的城市里
  取出今天的两座：**00:00–12:00 是第一座，12:00–24:00 换成第二座**，明天再换两座；
- 每 30 秒检查一次是否跨过 12:00，跨过就自动换片并更新文案；
- 副标题那行写着当前是哪一座、下一座是谁（「今天第 2 幅是 呼伦贝尔 · 明天 00:00 换成 婺源」），
  右侧小卡显示**下一幅**的封面，点它就进那座城市；
- 「画面动效 OFF」会连首屏短片一起暂停，省电模式不会偷偷放视频。

### 3. 其余实拍图

页面不是纯色底，而是「实拍照片 + 纸面质感」的组合：

| 位置 | 用的图 |
| --- | --- |
| 画廊首屏 | `assets/img/hero-dali-sunrise.jpg`（洱海日出） |
| 中段照片带 | `assets/img/band-three-pagodas.jpg`（崇圣寺三塔，辰时） |
| 交流页页头 | `assets/img/band-ancient-road.jpg`（永平·博南古道） |
| 收藏页页头 | `assets/img/band-cangshan.jpg`（苍山清碧溪） |
| 备用 | `assets/img/band-dali-night.jpg`（下关夜景，暂未使用） |

配合三件事做出质感：

1. **曲线收边**：每个照片区块的上下边缘用 SVG 弧线收口（`.curve`），
   参考的是 nomads.com 首图那种「照片不是硬切边」的处理；
2. **导航浮在照片上**：照片压在导航下时，导航自动变透明衬白字（`body.hero-mode`），
   滚过照片后回到纸色——由 `app.js` 的 `updateHeroMode()` 控制；
3. **全站颗粒**：`body::after` 铺一层极淡的噪点（SVG feTurbulence，透明度 5%），
   让大面积纸色像印刷纸而不是纯色块。

照片全部来自你提供的那条大理素材，用工具抽帧生成：

```bash
# frame <源视频> <输出.jpg> <秒> [宽度] [JPEG质量] [再裁掉底部百分比]
swift tools/video.swift frame "大理/1.mp4" assets/img/hero-dali-sunrise.jpg 31.5 2200 0.78 0
```

最后一个参数用来裁掉素材自带的字幕等元素；给 0 表示保留完整构图。

## 画面是怎么来的

没有用任何图片或视频素材。每张卡片是一个 `<canvas>`，
由 `scenes.js` 以约 30fps 逐帧绘制：天空渐变、太阳/月亮、云、雾、
山脊/喀斯特峰林/沙丘、水面波光、海浪、飘雪、雨、飞鸟、骆驼、
竹筏帆船、经幡、亭台楼阁、草原羊群、竹林垂柳、椰树、灯火、萤火。

画面只在进入视口时绘制（`IntersectionObserver`），离开视口即暂停，
所以 16 张卡片同时展示也不会卡。顶栏的「画面动效 ON/OFF」可全局暂停，
系统开启「减弱动态效果」时会自动暂停。

### 画面配方（`city.scene`）

| 字段 | 取值 |
| --- | --- |
| `palette` | `goldenHour` `dawnMist` `brightDay` `snowNight` `desertSunset` `springRain` `clearNight` `dusk` `grassDay` `cityNight` `bambooMist` |
| `horizon` | 地平线位置，0–1（水面 / 前景的起点） |
| `sun` | `{ x, y, r, glow, crescent }`，`crescent:true` 画成月亮 |
| `stars` | `{ density, milkyway }` |
| `clouds` | `{ count, band:[上,下], scale, opacity, speedScale }` |
| `fog` | `{ bands, from, to, opacity, thickness }` |
| `terrain` | `ridges` 山脊（`snowcap` 可加雪顶）/ `karst` 喀斯特峰林 / `dunes` 沙丘 / `none` |
| `landmark` | `{ variant, x, base, scale, lights, count, rows }`，variant 见下 |
| `prayerFlags` | `{ y, count }` 经幡 |
| `water` | `lake` / `sea` / `river` / `none`，`waterOpts` 里 `sunColumn` 会画出水面波光柱 |
| `waves` | `{ count }` 海滩浪花 |
| `boats` | `{ count, kind:'raft' 竹筏 / 'sail' 帆船, x, y, scale, speed }` |
| `camels` | `{ count, x, y, scale }` 驼队 |
| `birds` | `{ count, y, dir, color }` |
| `foreground` | `grass` 草地（可带 `sheep` 羊群）/ `rapeseed` 油菜花 / `snow` 雪地 / `bamboo` 竹林 / `willow` 垂柳 / `palms` 椰林 / `none` |
| `particles` | `snow` / `petals` 花瓣 / `rain` / `sand` 沙尘 / `fireflies` 萤火 |
| `vignette` | 四角压暗程度，0–1 |

`landmark.variant` 可选：`pavilion` 亭、`pagoda` 塔、`huizhou` 白墙黑瓦、
`diaojao` 吊脚楼、`dome` 圆顶教堂、`lighthouse` 灯塔、`yurt` 毡房、
`bridge` 石拱桥、`redroof` 红瓦房、`oldtown` 土墙老城、`city` 城市天际线。

### 加一座新城市

在 `data.js` 的 `CITIES` 里加一条，最少需要：`id / name / region / cat / tagline /
intro / size / tags / stats / months / facts / author / likes / comments / scene`。

- `size`：`wide` 或 `medium`（16:10 / 4:3）、`tall`（3:4）、`short`（16:9）
- `stats.best` 用**从 0 开始的月份索引**（0=1 月，11=12 月），
  跨年窗口（如 11 月–次年 4 月）会自动合并显示
- `months.temp / comfort / costIndex` 各 12 个数字

## 用实拍短片替代绘制内容

大理目前用的是实拍短片：`assets/video/dali.mp4`（720p、无音轨、4.4 秒循环）。
在卡片和详情页里，视频会自动替代原本的程序化画面；
离开视口自动暂停，「画面动效 OFF」也会一起停，不会偷偷耗电。

把视频接进一座城市，只需要在 `data.js` 里加一段：

```js
video: {
  src: 'assets/video/你的城市.mp4',
  poster: 'assets/video/你的城市-poster.jpg',   // 未播放/加载中显示的封面
  label: '实拍短片 · 洱海日出',                  // 卡片左上角显示
  credit: '视频素材：用户提供',                  // 详情页上的来源标注
  focus: '18% 50%'                              // 可选：卡片裁切构图，默认居中
}
```

删掉这个字段，卡片就会回到 `scene` 里配置的程序化画面 —— 两条路随时可以切。

### 剪片子：tools/video.swift

不需要装 ffmpeg，脚本用的是 macOS 自带的 AVFoundation：

```bash
# 1) 先看素材：生成 12 帧的预览图，挑出要剪的区间
swift tools/video.swift contact "大理/1.mp4" /tmp/sheet.png 12

# 2) 剪出网页用短片（720p / H.264 / 去掉音轨）+ 封面图
swift tools/video.swift clip "大理/1.mp4" assets/video/dali.mp4 29.95 4.4 assets/video/dali-poster.jpg
```

脚本顺手处理了两个容易踩的坑：

- **自动去掉素材上下自带的电影黑边**（航拍/纪录片素材很常见），
  并按画面实际比例输出（大理这条是 1280×544）；
- **输出高度强制取偶数**：H.264 的 4:2:0 色度采样要求偶数高度，
  否则 Safari / Chromium 会直接报「无法播放媒体」。

### 为什么需要 serve.py

Safari / WebKit 播放 `<video>` 时**要求服务器支持 HTTP Range 请求**，
普通的 `python3 -m http.server` 不支持，视频会直接播不出来。所以本地预览请用：

```bash
python3 serve.py            # http://127.0.0.1:8777
```

直接双击 `index.html`（file:// 方式）也能正常播放视频，只是收藏和发帖记录不一定会保存。

### 从免版权素材站找实拍短片

**当前状态：57 座用实拍短片**（多数来自 Pixabay，大理、杭州是用户自己拍的），
**12 座用绘制画面**（`CITY_VIDEOS_HOLD`）。素材台账在 `data.js` 的 `CITY_VIDEOS`，
署名在 `assets/stock/credits.json`。

`tools/stock.py` 负责「找素材 → 判断能不能用 → 下载 → 加速 → 生成封面 → 记账」整条链路，
处理环节复用 `tools/video.swift`（所以同样免装 ffmpeg）。

```bash
# 1) 直接给视频文件地址（不需要 key，最省事）
python3 tools/stock.py --url "https://.../xxx.mp4" --city dali \
    --label "实拍 · 洱海日出" --credit "Pexels · 摄影：某某" --speed 4 --duration 20

# 2) 用 API key 搜索（Pixabay / Pexels 都支持，按 key 格式自动识别）
export PIXABAY_API_KEY=你的key
python3 tools/stock.py --city dunhuang --speed 4 --duration 20 --width 960 --max-mb 2.2

# 3) 批量处理（每座城市用内置的搜索词）
python3 tools/stock.py --batch guilin,zhangjiajie,sanya --speed 4 --duration 20 --max-mb 2.2

# 巡检：只看搜到什么，不下载
python3 tools/stock.py --list-all

# 探路：用真地名巡检，只打印候选标签，判断这座城市到底有没有素材
python3 tools/stock.py --batch xian,lhasa,suzhou --probe

# 点名取用：探路时人工确认过 id 的素材，写进 CITY_PICK 后一次取回来
python3 tools/stock.py --batch yangshuo,haixi,macau --pick --speed 3.5 --duration 14
```

key 可以放环境变量，也可以写进 `assets/stock/pixabay-key.txt`（一行，别提交到公开仓库）。

关键参数：

| 参数 | 作用 |
| --- | --- |
| `--speed 4` | 4 倍速：20 秒素材压成 5 秒循环，延时摄影的节奏 |
| `--duration 20` | 从源片取多少秒 |
| `--width 960` | 输出宽度（正好匹配素材站的小尺寸版本，只下载一次） |
| `--max-mb 2.2` | 单片体积上限，超了编码器自动降码率 |
| `--min-motion 2.0` | 运动量下限，低于它就换下一条候选 |
| `--tries 4` | 最多试几条候选 |
| `--preview` | 额外生成分帧图（存到 `assets/stock/sheets/`），方便人工复核 |
| `--probe` | 探路模式：用内置的真地名搜索词巡检候选标签，只查询不下载 |
| `--pick` | 点名取用 `CITY_PICK` 里人工确认过的素材 id（按顺序优先） |
| `--require` | 手动指定标签白名单（逗号分隔），候选标签必须命中其中之一 |
| `--no-require` | 关掉标签硬门槛，回到旧的排序方式 |

**三道自动筛选**（这个库的中国素材很少，必须筛）：

1. **内容相关性**：搜索时先搜「关键词 + china」，再搜关键词本身；
   标签里带日本/韩国/墨西哥/欧洲/动物等的候选直接丢掉，带 china/chinese/asia 的排在前面。
   另外特写类标签（茶席、切菜、气泡、散景、书法…）也会被丢掉——踩过坑：
   搜「chinese temple mountain mist」返回过一整个茶席，搜「苏州水乡」返回过切菜的手。
2. **运动量**：`video.swift motion` 采样 8 帧算平均亮度差。
   固定机位空镜约 0.7–1.1，有推拉摇移或水流云动的 3–20。
   4 倍速会把慢镜头变得明显，所以阈值按倍数放宽。
3. **标签硬门槛（`CITY_REQUIRE`）**：每座城市列一组「必须命中的标签」，
   例如阳朔要 `karst / river / guilin`，茶卡盐湖要 `salt / lake`。
   一条候选都没命中就**不采用**，宁可留绘制画面——这是防「拿别国画面充数」的最后一道闸。

> **诚实说明**：自动筛选只能保证「不是明显不对的内容 + 画面在动」，
> 不能保证「就是这座城市」。Pixabay 上中国城市的素材很有限，
> 有些城市拿到的只是气氛接近的镜头（例如桂林那条，画面确实是漓江喀斯特，
> 而苏州拿到的更像手作特写）。所以卡片上统一标的是「实拍氛围短片」而不是「XX 实拍」。
> 要精确到城市，还是得靠实拍或采购——这也是这个站点真正的长期成本。

复核素材最快的办法：打开 `assets/stock/sheets/` 里的分帧图（每格是一帧，标了时间），
不满意就换城市关键词重跑那一条，台账会自动更新。

也可以直接开两个复核页（都放在 `tools/` 里）：

- `tools/review.html`：把全部封面拼成一屏，一眼看出哪条素材跟城市对不上；
  支持分片放大看，例如 `review.html?from=1&to=12&cols=4`。
- `tools/sheets.html?cities=yangshuo,suzhou`：把某几座城市的**分帧图**竖着排，
  一次看 6 帧，确认那条片子从头到尾都是对的内容（封面帧容易骗人）。

2. **不能原样转卖**素材（比如把下载的片段当素材包再卖），放进你的网站里用没问题；
3. **不能暗示代言**：画面里有可识别人物或品牌时，不要写成「某某推荐」这种。

```js
      video: {
        src: 'assets/video/dali.mp4',
        poster: 'assets/video/dali-poster.jpg',
        label: '实拍短片 · 洱海日出',
        credit: 'Pexels · 摄影：某某'   // 署名，建议保留
      },
```

### 不想要程序化画面了？

`data.js` 顶部有个开关：

```js
SETTINGS: {
  drawnFallback: true   // true：没有实拍短片的城市用绘制画面兜底
}                        // false：改成斜纹占位卡 + 「实拍待接入」，提醒去补素材
```

**现在的分工**：57 座城市用实拍短片，12 座（`CITY_VIDEOS_HOLD` 里那些）用绘制画面；
但只要某条实拍出问题（文件缺失、编码不支持、加载失败），那张卡片会
**自动换回程序化画面**，角标也从「实拍画面」改成「实时绘制」，用户不会看到破图。
`scenes.js` 因此保留 —— 它是备用方案。

关掉 `drawnFallback` 则连兜底都不要：没有实拍的城市显示斜纹占位卡 +「实拍待接入」，
提醒去补素材。两种取向按需切换。

> 一个现实提醒：Pexels / Pixabay 上**中国城市的实拍素材很少**，搜「Dali China」基本搜不到真正的大理。
> 拿到的多半是「气氛对得上」的镜头（湖面日出、沙丘、草原）。建议分两类处理：
> 真到过那座城市的素材才标「实拍 · 城市名」，否则老老实实标成「氛围短片 · 湖光」，
> 别让用户以为这是当地实拍——这一条比技术实现重要得多。

## 账号与内容分级（注册才能看更多）

产品规则（2026-09-27 定）：**做成真产品；发帖免费；注册后才能看更多；数据要真实、慢慢补。**

前端已经按这套规则跑通（`index.html` 的 `#auth` 弹层 + `app.js` 里的 `isMember()` 系列）：

| | 游客（未注册） | 注册用户（免费） |
| --- | --- | --- |
| 画廊 69 张卡 + 城市气质 | 能看 | 能看 |
| 卡片数据层（月成本/舒适度/天气/交通/奶茶/景点） | 只露前 2 条，其余「注册可见」 | 全 6 条 |
| 卡片底部的成本与网速 | 写成「注册可见」 | 正常显示 |
| 城市详情「旅居速览」 | 只露前 2 项 | 全 6 项 |
| 城市详情「住下来会遇到的细节」 | 整段锁住 | 全 9 条 |
| 社区笔记 | 只露最新 3 条 | 全部 |
| 收藏 / 发帖 / 回复 / 点赞 | 点一下弹注册 | **全部免费** |

数量都在 `data.js` 的 `SETTINGS.account` 里（`guestRows` / `guestStats` / `guestPosts`），
想放松或收紧改一行就行。

> ⚠️ **现在的分级是纯前端的**：数据本来就在浏览器里，懂技术的人能扒出来。
> 这是原型阶段的取舍——先把产品规则和转化路径跑通。接后端时，
> 这四条判断必须搬到服务端（接口按登录态返回不同字段），否则等于没锁。

注册流程目前是「手机号 + 6 位验证码 + 昵称」，原型阶段不真发短信（验证码随便填 6 位），
账号只存在本机 localStorage。真上线要接短信服务商（阿里云/腾讯云短信）与用户表。

## 数据口径（重要）

城市名称、省份、标签、气候规律都是公开常识整理，可以直接用。

但 **`旅居指数` `月均成本` `网速` `月租区间` 这些数值目前是示例口径**，
目的是把交互和视觉先跑通，不能当作真实结论对外发布。
正式上线前建议：

1. 逐城校准，每个数值标注**来源**和**更新时间**（页脚已有提示位）；
2. 网速这类变动大的字段，标注「实测中位值 / 样本量 / 采集月份」；
3. 成本按「含房租与日常」还是「仅房租」明确口径，避免用户误解；
4. 社区笔记才是你真正的差异化数据，尽早把真实用户的笔记积累起来。

## 已知取舍与下一步

- 社区目前是前端本地存储（localStorage），只在这台浏览器可见；
  下一步需要接后端或现成的开源社区方案（发帖、回复、点赞、关注都已在 UI 上跑通）。
- 城市画面是程序化生成的意象，不是航拍实拍。想更进一步可以做成
  「实拍照片 + 程序化动效叠加」（例如真实照片做底、光晕与粒子做层次）。
- 尚未做的：账号体系、私信、约伴活动的报名、按月份筛选城市、
  多个城市并排对比、移动端专属手势。
